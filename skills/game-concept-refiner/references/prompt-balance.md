# 下游 Prompt 的约束平衡

## 应该锁定

只锁定改变项目身份的内容：

- 核心体验和最重要的玩法联系；
- 用户明确选定的世界观种子；
- 用户明确选定的视觉参考及借鉴层级；
- 必须继承的数据或状态关系；
- 首版范围和最终交付物。

## 应该保持开放

通常交给规划型 AI 判断：

- 具体单位、职业和技能；
- 数值与经济循环；
- 关卡数量和完整剧情章节；
- 文件目录与模块拆分细节；
- 具体引擎和技术栈（用户没有硬限制时）；
- 最终平衡方法和次级系统。

## 过度具体的信号

- 为每种单位规定完整技能；
- 提前列出所有系统和 UI 页面；
- 把讨论中的一个可能性写成“必须”；
- 要求规划 AI 按大量固定章节输出分析报告；
- 指定技术栈只是因为熟悉，而非因为适合首版。

## 过度模糊的信号

- 只写“做一个有创新的游戏”；
- 只给类型标签；
- 没有说明多个玩法如何互相影响；
- 没有明确首版做到什么程度；
- 没有说明下游 AI 最终交付什么。

## 推荐骨架

```text
请为一个从零开始的游戏生成一份供后续 AI Agent 执行的单一 Markdown 计划文件。你负责自行完成必要的玩法、技术与架构决策，不要输出额外分析。

必须保留的核心方向：
[只列用户确认的固定锚点]

除上述锚点外，其余玩法、系统、关卡、角色能力、叙事细节和技术方案由你自行判断。优先验证核心体验，避免无关系统和过早抽象。

首版应是一段完整可玩的纵向切片，也能自然保留为正式游戏的起点。最终只输出一个 Markdown 执行文件，使后续 Agent 能按实际开发顺序直接实现。
```

根据具体项目改写，不要机械复制。

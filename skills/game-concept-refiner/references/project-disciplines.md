# 项目纪律参考

这些原则提炼自 `asashiki/vibe-game` 的想法池。按需使用，不要把全部内容强塞进每个项目。

## 立项与玩法

- 优先选择用户具有玩家级鉴赏力的品类；不要仅因技术上能做就立项。
- 先找到一句话可说明的核心体验或 twist。
- 第一个里程碑优先验证项目最大的玩法或技术风险，而非先做完整框架。
- 玩法型项目先做灰盒，确认“真好玩”而不是“概念听起来好玩”。
- 首个纵向切片可以直接成为正式游戏第一关，避免做完即废弃。
- 开工前搜索 GitHub 和现成资产，寻找可复用轮子。
- 给单项目设置资产总量上限，防止内容量先于核心体验膨胀。

## 世界观种子

- 立项时只需一段种子：这是什么地方、谁在与谁冲突、整体基调是什么。
- 种子必须来自用户真正想要的东西，而非 AI 顺手生成的标准故事。
- 不在玩法尚未成立前扩写完整设定集。

## 美术风格关卡

- 灰盒成立后、量产资产前，先生成 3–5 个刻意相距很远的风格样板。
- 由用户选定一个方向，再形成风格圣经。
- 风格圣经使用参考图作为锚，并写明确负面清单。
- 避免只靠“精美、未来、二次元、霓虹”等形容词堆叠。
- 参考某款游戏时，分析视角、地图复杂度、角色比例、信息层、立绘和演出方式，而非只引用名称。

## 资产实现优先级

1. **代码即美术**：几何、shader、粒子、后期处理和代码动效。
2. **免费素材包打底**：使用许可清晰的 Kenney、Quaternius、OpenGameArt、itch CC0 等。
3. **少量关键生成资产**：先建立风格锚，再生成带目标文件名、视角、尺寸和透明背景要求的 prompt 清单。

- 避免依赖生成式逐帧动画；优先使用静态图配合位移、旋转、缩放、挤压和粒子。
- 3D 原型可采用概念图转模型流程；正式角色优先寻找许可合适的现成模型。
- 不用低质量纯蜂鸣代替成品音频；使用精选免费音效或专门的 AI 音效工具。
